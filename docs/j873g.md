# J873g / T8152 initial bring-up

This port targets the M6 Mac mini identified by `J873g`, `Mac18,5`, chip
`0x8152`, board `0x24`. It provides a proxy using the firmware's
DockChannel/KIS console, architectural MMU/cache setup and inherited framebuffer.
It deliberately stops at the proxy instead of automatically loading payloads.

The measured MIDR parts are `0x072` (E and M cores) and `0x073` (P cores).
They do not inherit M4 fast-IPI or implementation-defined CPU tuning. PMGR2,
DCP reinitialization, USB cold initialization, storage and
automatic Linux device-tree preparation remain outside this initial port.

Native SMP starts all twelve CPUs on explicit request using the PMGR2 CPU-release
map. See [SMP qualification](j873g-smp.md) for the supported dispatch path and
reset requirements.

## Failure cases and end-to-end qualification

Before changing this path, account for a mismatched board, an incorrect console
channel, watchdog resets, unsupported Apple system registers, MMU/cache faults,
an inherited framebuffer outside ordinary RAM, accidental legacy PMGR writes,
and a chainload over active secondary CPUs. A build alone cannot exclude these.

Build with `make -j8` using the documented AArch64 toolchain. Preserve the installed
recovery image. From a fresh single-CPU m1n1 recovery session, verify the complete
target identity, hash the candidate binary, transfer it to RAM and verify its
readback before chainloading. Never chainload over running secondary CPUs.

Capture the build ID and `J873g: KIS bring-up with native SMP` banner, then verify proxy
NOP, boot arguments, the live ADT identity, an allocated RAM write/readback and
architectural counter progress. Save the console log, exact source commit,
binary SHA-256 and a machine-readable receipt. Reboot into the preserved recovery
image on failure; identify the host USB port afresh before any reset.

Linux handoff qualification is separate from the native SMP checks.
