# M5 secondary CPU bring-up

T8142 has six E cores and four P cores. Its global PMGR start/stop mask uses
the dense ADT CPU index. The per-cluster release mask remains core-relative.
The P-core MPIDR also contains Aff2=1, which is absent from ADT `reg`.

Each core receives its permanent reset stack before release. M5 secondaries
use WFE/SEV for m1n1 call dispatch and stay off the shared console during
initialization. Older resident reset vectors may point into the replacement
image's consumed Mach-O header. In that case a bounded RAM relay redirects
reset to the current vector table; live code and unrelated memory are rejected.
The installed bootloader is unchanged.

Build with `make RELEASE=1`, then RAM-chainload `build/m1n1.macho` using a
client matching the resident proxy ABI. Once this candidate is running:

```sh
python3 proxyclient/tools/validate_t8142_smp.py \
    --device /dev/cu.kis-00100000-ch-0 --output smp-proof.json
```

The device path is host-specific. The tool requires a J813/T8142 KIS target,
starts secondaries, checks each secondary's MPIDR and executes 20 independently
checked computations per core. It retains a JSON artifact and returns failure
if any core is missing or returns an incorrect result. Recover with VDM after
a timeout instead of reusing an uncertain boot.

On J813, all nine secondaries passed (including CPU0); the boot CPU is CPU6.
This establishes m1n1 dispatch on all ten cores. Linux additionally needs M5
register preservation around WFI: without it all ten CPUs start, but secondary
idle tasks return with cleared registers and panic. Hotplug, deep sleep and
KVM are outside this qualification.
